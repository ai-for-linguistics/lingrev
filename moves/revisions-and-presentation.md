# Revising the paper and the report

## A new manuscript version

Identify the old and new versions explicitly. Compare the relevant text, figures, methods, and results. Keep comment IDs stable. For each affected comment, record whether it still applies, has changed, is resolved, or should be retracted, with the reason and evidence. Distinguish a change to the manuscript from a correction to the assistant's earlier reading. Keep unchanged evidence gaps until the corresponding checks are performed.

Update the single prose Overview, the author's goals when changed, identified strengths, Comments, Coverage & sources, review.md, changes.md, and progress in brief.md. Rebuild the current report. Do not simply append a second review without reconciling the first.

## Alternative presentations

Local wording, terminology, titles, main headlines, abstract variants, captions, and whole-paper structure can all be useful feedback. Show actual current/proposed passages or outlines side by side and explain substantive changes. Preserve linguistic judgments, notation, meaning, and evidential strength. Do not rewrite a scientific problem into a stronger claim.

When several directions could work, put generation offers in Comments with short bullet-point emphases and copyable instructions. For example, propose five abstracts, several title/headline pairs, or three outlines. Make the tradeoffs clear and let the author select or combine them. Generate versions directly if already requested; otherwise an offer is a useful next action. Do not imply that draft text already exists when it has not been generated.

New arguments, experiments, figures, a slide deck, or a handout can be outputs too. Use outputs/ for additional artifacts and keep source manuscripts intact unless edits are requested. Keep original and proposed material distinguishable.

## Changing the review or report

The author can change scope, priorities, categories, ordering, and report views at any time. “Make the report simpler” or “Show unresolved theoretical questions in a new tab” are legitimate requests. Preserve evidence, stable IDs, and history while adapting the interface.

The default is the current template: Overview, Comments, Coverage & sources, How to. Overview has one prose summary and no duplicate action box. Comments contain the specific tasks and copyable instructions. How to stays a broad invitation with the setup figure first and possibilities figure second, side by side.

For project-specific HTML changes, start from the current toolkit template, merge custom content into custom/report.html, and retain its rendering markers, interface IDs, and template-version metadata. A stale custom template must be adapted, not made “current” by changing its version tag alone. Do not overwrite unrelated custom content. Rebuild and check the resulting report after each substantive revision.
