# Optional review tasks

The paper and the author's goals determine the work. Start with METHOD.md and produce the first review using the current dashboard template. These playbooks are available extensions, not required stages or a checklist to fill.

| Input or request | Read |
| --- | --- |
| Supplied literature, linked papers, comparisons, counterevidence | [literature.md](literature.md) |
| Code, data, existing plots, reproducibility, new analyses, online frequency checks | [code-and-data.md](code-and-data.md) |
| Definitions, principles, derivations, formalization, Lean, linglib comparison | [formal-analysis.md](formal-analysis.md) |
| A new manuscript version, rewrites, title/abstract/structure alternatives, new report views | [revisions-and-presentation.md](revisions-and-presentation.md) |

A paper alone is enough. Supporting material can be PDFs, source, URLs, code, data, figures, or an entire working folder. Inventory what is actually available and respect exclusions. Use the relevant playbook when the task arises, without making the author select a workflow first.

Preserve the current report design: one prose Overview, a sortable expandable Comments table, Coverage & sources, and a simple How to panel. Put specific proposals, comparisons, tests, generation offers, and instructions in Comments. Save the first useful review before optional extended work. Continue work already requested within its budget. Otherwise propose a concrete bounded next step, and ask only for information or authorization that is actually missing.

The fictional example illustrates some outputs. It does not define what counts as useful feedback or limit which inputs and tools can be used. Every check must say how it was obtained and what remains open.
